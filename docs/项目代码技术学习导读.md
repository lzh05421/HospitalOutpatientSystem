# 医院门诊挂号与药品管理系统代码技术学习导读

本文档用于帮助快速熟悉本项目代码。项目主要采用 C++、Qt Widgets、Qt Network、Qt SQL、JSON、MySQL、CMake 等技术，实现医院门诊挂号、候诊、接诊、检查、处方、库存、收费、统计、日志和权限配置等功能。

## 1. 项目整体结构

| 目录 | 作用 | 主要技术 |
|---|---|---|
| `client/` | 医院端和患者端桌面客户端 | Qt Widgets、QTcpSocket、QJsonObject |
| `server/` | TCP 服务端、路由鉴权、业务模块、数据库访问 | QTcpServer、QTcpSocket、Qt SQL、MySQL |
| `common/` | 客户端和服务端共用协议 | JSON Lines、Request/Response 封装 |
| `database/` | 建库建表和演示数据 | MySQL、外键、索引、事务表设计 |
| `config/` | 服务端运行配置 | ini 配置、ODBC/QMYSQL 数据库连接 |
| `scripts/` | 构建和运行脚本 | PowerShell、Shell |
| `tests/` | 自动化和源码规则测试 | Qt Test、CTest |
| `docs/` | 文档、图表、课程设计生成脚本 | Python、Pillow、docx XML |

## 3. 一次业务请求的完整链路

以“挂号管理”发起一次保存请求为例：

1. 用户在客户端页面点击按钮。
2. 页面构造 `common::Request`，设置 `module`、`action`、`payload`。
3. `ApiClient::send()` 使用 `Protocol::encodeRequest()` 把请求转成 JSON Lines。
4. `QTcpSocket` 把请求发送给服务端。
5. `ClientConnection::onReadyRead()` 接收一行 JSON 请求。
6. `Protocol::tryDecodeRequest()` 解析成 `Request` 对象。
7. `RequestRouter::route()` 做登录校验、权限校验、模块分发。
8. 对应 `ModuleService` 子类处理业务，例如 `RegistrationService`。
9. 业务服务通过 `DatabaseManager` 访问 MySQL。
10. 服务端返回 `common::Response`。
11. 客户端 `ApiClient::onReadyRead()` 解析响应并通知页面刷新。

这条链路对应的核心文件：

| 环节 | 文件 |
|---|---|
| 协议定义 | `common/include/common/Protocol.h` |
| 协议编码解码 | `common/src/Protocol.cpp` |
| 客户端发请求 | `client/src/ApiClient.cpp` |
| TCP 接入 | `server/src/HospitalServer.cpp`、`server/src/ClientConnection.cpp` |
| 路由鉴权 | `server/src/RequestRouter.cpp` |
| 业务处理 | `server/src/modules/*.cpp` |
| 数据库访问 | `server/src/DatabaseManager.cpp` |

## 4. 客户端代码怎么看

### 4.1 主窗口和菜单

文件：`client/src/MainWindow.cpp`

作用：

- 使用 Qt Widgets 搭建医院端主界面。

- 根据角色权限调用 `addIfAllowed()` 决定显示哪些功能模块。

重点技术：

| Qt 样式表 | 控制界面颜色、边框、字体 |
| lambda 表达式 | 用 `addIfAllowed` 简化模块添加逻辑 |

### 4.2 客户端通信

文件：`client/src/ApiClient.cpp`

作用：

- 封装客户端和服务端之间的 TCP 通信。
- 保存登录后的 Token、角色、权限、患者身份等会话信息。
- 发送请求时自动补充 `Authorization: Bearer token`。
- 接收服务端响应后解析 JSON，并通过 Qt 信号通知页面。

重点技术：

| 技术 | 作用 |
|---|---|
| `QTcpSocket` | 客户端 TCP 连接 |
| Qt signal/slot | 连接成功、收到数据、出错时触发回调 |
| `QJsonObject` | 保存请求参数和响应数据 |
| Bearer Token | 服务端鉴权使用 |
| JSON Lines | 每个请求/响应占一行，便于 TCP 拆包 |

### 4.3 通用页面基类

文件：`client/src/pages/ModulePage.cpp`

作用：

- 封装多数管理页面的通用表格、刷新、查询、新增、修改、删除、导出等逻辑。
- 患者、科室、医生、挂号、库存、统计等页面复用它。

重点技术：

| 技术 | 作用 |
|---|---|
| 继承 | 具体页面继承 `ModulePage`，复用表格逻辑 |
| `QTableWidget` | 展示业务数据表 |
| `QJsonArray` | 保存服务端返回的行数据 |
| 虚函数 | 子类通过覆盖函数定制行为 |

## 5. 服务端代码怎么看

### 5.1 服务端入口

文件：`server/src/main.cpp`

作用：

- 创建 `QCoreApplication`。
- 读取 `config/server.example.ini`。
- 创建 `DatabaseManager` 并连接 MySQL。
- 创建 `RequestRouter` 和 `SessionManager`。
- 创建并注册 16 个业务服务。
- 启动 `HospitalServer` 监听端口。

重点技术：

| 技术 | 作用 |
|---|---|
| `QCoreApplication` | 无界面 Qt 服务端事件循环 |
| 配置文件 | 控制服务端端口和数据库连接 |
| 依赖注入 | 把 `DatabaseManager` 传给各业务服务 |
| 服务注册表 | `router.registerService(module, service)` 建立模块名和服务对象映射 |

### 5.2 TCP 服务器

文件：`server/src/HospitalServer.cpp`

作用：

- 使用 `QTcpServer` 监听客户端连接。
- 每来一个连接就创建一个 `ClientConnection` 对象。

重点技术：

| 技术 | 作用 |
|---|---|
| `QTcpServer` | TCP 服务端监听 |
| `newConnection` 信号 | 有新客户端连接时触发 |
| `QTcpSocket` | 表示某一个客户端连接 |

### 5.3 连接处理

文件：`server/src/ClientConnection.cpp`

作用：

- 读取客户端发来的 TCP 数据。
- 按换行拆分 JSON Lines 请求。
- 调用 `RequestRouter::route()` 分发业务。
- 把响应编码后写回客户端。
- 额外支持扫码支付模拟 HTTP 链接。

重点技术：

| 技术 | 作用 |
|---|---|
| TCP 粘包处理 | 用 `m_buffer` 缓存数据，按 `\n` 拆包 |
| 最大帧限制 | 防止单个请求过大 |
| JSON 解码 | 将网络数据转成业务请求 |
| HTTP 模拟接口 | 用于扫码支付演示 |

### 5.4 路由与权限

文件：`server/src/RequestRouter.cpp`

作用：

- 根据请求里的 `module` 和 `action` 找到业务服务。
- 统一处理登录校验、角色权限校验、患者身份注入、操作日志、审计明细。
- 防止客户端直接伪造内部字段。

重点技术：

| 技术 | 作用 |
|---|---|
| 路由表 | `QHash<QString, ModuleService*>` 保存模块到服务的映射 |
| Token 鉴权 | 从 `Authorization` 或 `request.token` 取 Token |
| RBAC 权限 | 根据角色和权限码决定是否允许访问 |
| 审计日志 | 写入 `operation_logs` 和 `audit_log_details` |

### 5.5 数据库管理

文件：`server/src/DatabaseManager.cpp`

作用：

- 根据配置连接 MySQL。
- 支持 `QODBC` 和 `QMYSQL` 两类 Qt 数据库驱动。
- 提供 `ensureOpen()`、`database()` 等统一数据库入口。
- 初始化部分演示目录数据。

重点技术：

| 技术 | 作用 |
|---|---|
| Qt SQL | 通过 `QSqlDatabase`、`QSqlQuery` 操作数据库 |
| ODBC | Windows 下连接 MySQL 的常用方式 |
| SQL 参数绑定 | 使用 `query.bindValue()` 避免字符串拼接 SQL |
| 自动重连 | 数据库断开后尝试重新打开 |

## 6. 服务端业务模块

业务服务声明文件：`server/include/server/modules/ModuleServices.h`

业务服务实现目录：`server/src/modules/`

每个业务服务都继承 `ModuleService`，并实现：

```cpp
common::Response handle(const common::Request& request) override;
```

这表示所有业务模块都用统一入口接收请求，再根据 `request.action` 执行不同操作。

| 服务类 | 模块名 | 作用 |

| `PatientService` | `patient` | 患者档案新增、查询、修改 |
| `RegistrationService` | `registration` | 挂号、退号、候诊队列、医保预校验 |
| `DepartmentService` | `department` | 科室维护 |

| `DoctorService` | `doctor` | 医生资料和科室归属 |
| `ConsultationService` | `consultation` | 医生接诊、叫号、诊疗状态 |
| `ExaminationService` | `examination` | 检查项目、检查申请、结果录入 |
| `PrescriptionService` | `prescription` | 处方开立、审核、发药、退药 |
| `InventoryService` | `inventory` | 药品信息、入库出库、库存预警 |
| `BillingService` | `billing` | 账单、支付、医保模拟、退费 |
| `StatisticsService` | `statistics` | 收入统计、科室统计 |

## 7. 通信协议

文件：

- `common/include/common/Protocol.h`
- `common/src/Protocol.cpp`

请求结构：

```cpp
struct Request
{
    QString module;
    QString action;
    QString token;
    QJsonObject headers;
    QJsonObject payload;
};
```

响应结构：

```cpp
struct Response
{
    bool success = false;
    QString message;
    QJsonObject data;
};
```

字段含义：

| 字段 | 作用 |
|---|---|
| `module` | 要访问的业务模块，如 `registration` |
| `action` | 要执行的动作，如 `create`、`list` |
| `token` | 登录后获得的会话令牌 |
| `headers` | 类似 HTTP Header，用于保存 Authorization |
| `payload` | 具体业务参数 |
| `success` | 响应是否成功 |
| `message` | 提示信息 |
| `data` | 响应数据 |

## 11. 不建议逐行注释的原因

逐行注释会让代码变得很长，很多注释只是在重复代码本身，例如“创建按钮”“设置文本”。真正有价值的是在关键流程和复杂规则处说明：

- 为什么要这样设计。
- 用了什么技术。
- 数据从哪里来，到哪里去。
- 这个类在系统中承担什么职责。

如果需要在源码里加注释，建议只加在这些位置：

- `ApiClient::send()`：解释 Token 和 JSON Lines 请求发送。
- `ClientConnection::onReadyRead()`：解释 TCP 拆包和请求转发。
- `RequestRouter::route()`：解释鉴权、身份注入、服务分发和审计。
- 各业务服务的 `handle()`：解释 action 分发。
- 复杂业务函数，例如挂号医保校验、排班规则、处方发药、退费审核。
